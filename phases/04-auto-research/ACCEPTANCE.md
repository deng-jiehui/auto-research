日期：2026-10-26。已交付前置全文/证据、04-A 与 04-B1/B2/B3，支持任务、累计预算、计划/候选审核、逐篇分析及暂停重试；04-C1 矩阵、Claim 与正式报告已交付。04-C2 已补齐共用 UI 与 Web 接入，CLI 命令延期。下面保留各批历史记录，最新交付与验证见末尾共用 UI 小节。

## 04-A 首批能力（历史交付）

- 新增 DirectionService、领域对象、SQLite 迁移 008、版本历史及 HTTP。提案保存为 proposed，用户可编辑、确认、拒绝、归档；编辑重新进入待确认，旧 Revision 的确认返回 409。
- 方向包含代表论文、关键问题、待验证空白、可行性及来源会话。缺少代表论文标注依据不足，跨项目论文不可关联。
- 模型使用 `submit_research_result(kind=direction)`，只创建提案，不能填写批准状态。按 Turn 和内容生成稳定提交键，检查点重放复用同一提案。
- 项目侧栏/顶部增加研究方向入口，会话显示提案卡片。方向页可以编辑、确认、查看历史；“继续研究”新建会话并填入已确认方向的地址和版本，由用户检查后发送。
- 复用 `read_file`、`list_directory`、`search_files`，新增 research:// 应用适配，没有新增 get/read 方向工具。物理工作区继续使用原路径与确认策略，逻辑地址不可通过写文件或补丁修改。
- 当前 v3 只广告已实现能力；v1 保持原摘要工具，v2 保持全文工具及原读取参数，不混入方向/逻辑资料 schema。

## 手动体验

在 AutoResearch 根目录重启后端，前端沿用现有 Vite 启动方式：

```powershell
go run . serve --config config.arxiv.example.json
```

1. 打开项目的“研究方向”，手动新建提案，或在会话发送：“根据当前论文库整理并保存一个研究方向提案，说明关键问题、待验证空白和篇卡可行性；不要替我确认，也不要保存项目笔记。”

## 04-B3：逐篇分析、暂停与重试（v6 历史交付）

### 已交付

- 当前新任务为 single/multi-v6，v1–v5 保留旧工具 schema、结束条件和检查点恢复路径。继续使用同一主 Agent 的模型/工具循环，没有增加规划、阅读、写作模型节点。

- 扩展现有 submit_research_result(kind=paper_analysis)，保存方法、数据集、指标、代码、复现条件五字段。finding 必须引用同论文、同冻结文档的有效 Evidence；摘要不能冒充已核实的实验细节，缺少信息明确为 unknown/unverified/inference。
- 结果、内容版本、成功幂等记录和 research.progress 事件同事务提交。每篇结果立即可见，篇篇失败不丢其他成功项；全部项明确完成或失败时为 analyses_completed，仅表示逐篇处理结束。
- 暂停请求持久化，等待当前请求返回，在下次模型/工具调用前 graph.Interrupt；继续动作持久保存原 InterruptID，重启仍从原上下文恢复。取消停止新工作，已有成果保留。正式任务默认模型 64 次、工具 128 次，15 分钟执行段到安全边界暂停，另有 125 秒硬期限宽限。
- 篇篇重试仅重排失败项，沿用 Run、冻结文档和累计预算。整轮失败重试同样保留成功项；已完成任务再次执行或编辑冻结问题派生新 Run，用 PreviousRunID 关联旧成果。
- 会话与任务页展示进度、完成/失败计数、逐篇可展开分析、原文引用，以及暂停/继续/取消/失败重试。沿用原 SSE 和持久快照，调用统计继续使用现有 callback；未修改框架。

## 04-C1：证据矩阵、Claim 与版本化报告（single-v8，当前交付）

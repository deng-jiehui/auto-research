# AutoResearch：面向计算机专业学生的研究 Agent

[GitHub 仓库](https://github.com/deng-jiehui/auto-research) · [goHarness 框架](https://github.com/deng-jiehui/goHarhess)

这是一个基于 goHarness 的学生项目。它面向计算机专业学生，提供类似代码 Agent 的“项目 + 会话 + 上下文 + 任务”工作区，帮助用户发现、整理、理解、比较和复现论文，并自动形成可复核的研究报告。

AutoResearch 本身就是研究 Agent 产品。会话 Agent 负责讨论、整理资料和委派任务；自动调研交给独立 Research Agent，拥有自己的上下文、检查点和预算，在任务页审核和查看进度。会话只同步状态、结果摘要与成果位置，后续按需读取。论文复现和用户实验按后续阶段接入。项目内部采用交互、应用、领域和基础设施四层实现，应用直接用 goHarness Graph 定义主流程，复用模型/工具节点、观测与恢复。

项目示例问题：

> 2021 至 2026 年公开论文中，LLM Agent 在软件工程代码缺陷修复任务中使用了哪些工具调用方式？常见数据集、评测指标和主要局限是什么？

一次完整调研可以包括：拆解问题 → 生成检索式 → 查询公开论文元数据 → 去重与筛选 → 人工确认候选集 → 获取摘要或开放全文 → 抽取证据 → 跨论文比较 → 生成带引用报告 → 自我检查。用户也可以只要求整理已有论文、解释证据，或继续运行自己的实验。

## 项目形态

这是一个可以作为课程设计、毕业设计或作品集项目完成的前后端项目。第一版提供 Web 工作区，共用 UI 层支持未来接入 CLI，CLI 命令当前延期。不做通用互联网爬虫，也不承诺自动阅读付费论文；只接入公开来源，保存来源 ID、URL、抓取时间和原文片段。

阶段 01 本地项目工作台已实现：项目创建、设置、归档与恢复、确认删除，以及会话创建、重命名、归档与恢复均使用真实 API 和 SQLite。刷新或重启服务后可以继续读取。

阶段 02 默认使用一个模型节点与统一工具循环，论文、工作区、笔记和追问共享同一轮上下文。模型按需调用真实 `ask_user`，生成可编辑选项，回答后继续原上下文。Turn、消息、事件、笔记和检查点保存到 SQLite。工作区提供七个受控文件、Shell 和写入工具；写入确认及作用域仍由应用检查。默认 `fixture` 模式无需模型密钥，`remote` 使用 goHarness 的 OpenAI-compatible 适配器。阶段 03 已接入论文库、arXiv MCP、摘要读取和来源文本存储。

Agent 编排默认 `"agent_mode": "single"`。会话输入框上方可以点击“单 Agent / 多 Agent”，下一次发送生效，无需重启；会话偏好保存在当前浏览器。多 Agent 模式允许主助手按需调用 `run_subagent`，子 Agent 使用独立上下文。已有中断任务按原模式恢复。配置、数据流和测试步骤见 [Agent 双模式设计](phases/02-agent-runtime/AGENT_MODES.md)。

Agent 检索出的论文展示为卡片，可展开摘要并一键“加入论文库”，无需重新输入编号或让模型再执行归档。入库后按钮显示“已加入论文库”，右侧“参考资料”同步展示；点击标题或“查看论文”打开详情。左侧导航、项目顶部和右侧均可进入论文库，也可在论文库内搜索或手动添加。

项目笔记用于保留研究目标、关键结论和实验计划，在同一项目的会话间共享。新建会话或修改项目主题不会自动清空旧笔记；界面会注明笔记来自本轮、本会话历史或其他会话。模型应以当前研究目标为准，仅参考相关历史笔记。

会话底部可展开或打开笔记，每条笔记提供删除按钮，点击确认即可，无需输入名称。删除后不再进入后续新消息的项目笔记上下文，原聊天记录保留；已提交或正在执行的任务仍使用当时的上下文。后台保留删除标记与保存调用身份，避免重试旧轮次时复活笔记。中间会话区独立滚动，标题和输入框保持可见。

用户消息右下角提供“编辑消息”。点击后原位修改，选择“取消编辑”或“保存并重新发送”。保存后从该消息重新调用 Agent，保留此前对话，替换旧回复并移除后续对话；这些旧消息不再进入后续模型上下文。已保存的论文、项目笔记和文件修改保留。执行中的会话先等待完成，再编辑。

## 本地启动

需要 Go 1.24+、Node.js 22.12+ 和 npm。以下命令均在本项目根目录执行，需要两个终端。

先克隆独立仓库并下载后端依赖：

```powershell
git clone https://github.com/deng-jiehui/auto-research.git
cd auto-research
go mod download
```

终端一启动后端：

```powershell
go run . serve --config config.example.json
```

终端二安装锁定依赖并启动前端：

```powershell
npm --prefix web ci
npm --prefix web run dev
```

打开 [本地工作区](http://127.0.0.1:5173/)。后端默认监听 `127.0.0.1:8080`，Vite 将 `/api` 代理到后端；`GET /healthz` 与 `GET /readyz` 位于后端地址。当前 Go 服务只提供 API，构建前端不会自动启用静态文件托管；统一启动与打包在阶段 06 实现。

若更改后端端口，在启动前端的终端设置 `$env:AUTORESEARCH_API_URL = 'http://127.0.0.1:新的端口'`。配置中的 `data_dir` 相对于后端工作目录，默认持久数据位于 `data/autoresearch.db`；`data/` 已忽略，不进入版本库。结束前后端进程后，使用原配置重启即可继续访问已有项目。

前端左侧栏底部的“模型设置”可以在 `fixture` 和 `remote` 之间切换。选择 `remote` 后填写 OpenAI-compatible 端点、模型名称和 API Key，保存后新提交的研究轮次立即使用该模型。Key 仅保存在当前浏览器本地存储和后端进程内存中，不写入 SQLite，也不会由状态接口返回；服务重启后需要重新保存一次。

当前固定本地身份为 `local-user`。非回环监听必须配置 `auth_token_env` 并设置对应非空环境变量，API 才接受 Bearer Token；浏览器工作台当前面向默认本机模式，完整登录和远程访问在阶段 07 设计。`fixture` 模式使用离线模型；`remote` 模式启动时创建 OpenAI-compatible 模型并在执行中报告模型错误，不会降级为 fixture。

当前入口仅支持 `serve`。交互式 CLI 与离线调研命令延期，未来复用共用 UI 服务；`connector` 计划于阶段 05 实现，当前调用这些命令会明确失败。

## 真实 arXiv MCP 与会话工具

安装 [uv](https://docs.astral.sh/uv/)，保证 `uvx` 在 PATH 中；Windows 也可以把配置中的 `academic.command` 改为 uvx.exe 的绝对路径。启用真实来源：

```powershell
go run . serve --config config.arxiv.example.json
```

此配置固定使用 `arxiv-mcp-server==0.8.2`，后端启动时完成 MCP 握手和工具发现。学术来源与模型独立配置：启动后仍需在前端左下角的“模型设置”中配置真实模型，才能由模型自主规划论文任务；默认 fixture 模型仅用于离线流程演示。现有 `config.example.json` 保持离线来源，适合不访问外网的测试。

可在会话发送：

> 搜索 2021 到 2026 年关于 time series forecasting 的 3 篇 arXiv 论文，先介绍候选，暂不归档。

> 将上面的第一篇归档到本项目论文库，然后读取摘要，说明它和我的研究方向有什么关系。

也可以直接发送“将 arXiv:1706.03762 归档到本项目并读取摘要”，通过编号获取元数据。模型可调用 `search_papers`、`save_paper`、`list_papers`、`read_paper` 和 `ask_user`；项目身份由应用注入，归档与来源文本按身份/内容幂等保存。对已归档论文的后续提问会先查询项目论文库。

论文库支持“获取全文”、按块阅读、保存证据及点击原文高亮。`read_paper` 默认读取摘要；`section=fulltext` 获取或复用全文目录，`section=block` 按块阅读，`search_project_evidence` 检索项目原文，`save_evidence` 保存唯一逐字引用。全文优先 arXiv HTML，HTML 缺失时回退 PDF；PDF 提取需安装 Poppler 并配置 `document_pdf_command` 或将 `pdftotext` 加入 PATH。暂不支持扫描件 OCR 或向量检索。来源失败会明确报错，arXiv 返回限流时进入冷却，不会切换为演示数据。

实际联调与复测命令见[阶段三验收记录](phases/03-paper-library/ACCEPTANCE.md)。2026-10-23 已验证真实元数据获取及 Graph 关键词检索/归档/摘要读取。此前遇到的 HTTP 429 本轮未复现；指定论文的验收改用精确标题查询，避免宽泛关键词的相关性排序导致错误断言。上述真实 MCP 测试使用脚本模型固定工具选择，不消耗用户模型 Token。

故障定位与逐次 HTTP 取证方式见 [arXiv 搜索失败诊断](phases/03-paper-library/ARXIV-DIAGNOSIS.md)。第三方 MCP 会在先收到 429、重试超时后继续报告限流；具体历史触发条件仍未确定，不直接归因为 VPN。

## 完整本地版本验收（阶段 01–06）

- 固定问题可以生成稳定的检索计划；
- 公开来源返回的论文可以去重并保留来源信息；
- 每条综合结论至少关联一个 `paper_id` 和证据片段；
- 抓取失败可以从检查点恢复，不重新执行已完成阶段；
- 人工拒绝候选论文后，不进入全文分析；
- 离线 fixture 模式不依赖网络、API Key、Redis 或 Docker。

## 全文和证据体验（2026-10-25）

1. 打开项目论文库，选择已归档的 arXiv 论文，点击“获取全文”。
2. 在全文阅读器中点击章节块；“引用本段”可编辑原文、字段及研究解读。保存只接受该块内唯一的逐字原文。
3. 在“已归档来源与引用”点击“查看原文”，核对高亮；刷新仍打开同一冻结版本。
4. 获取失败会显示原因，可重试；原摘要与历史证据保留。“检查新版本”不会覆盖旧文本。
5. 会话可发送：“读取这篇论文的全文目录，按块检查方法，保存一条有逐字引用的 method 证据，并给出查看原文链接；不要保存项目笔记。”

可选配置：`"document_pdf_command": "C:/Tools/poppler/Library/bin/pdftotext.exe"`。所需 DLL 应位于解析器目录或 PATH；HTML 阅读不依赖 Poppler。运行项目的工作目录保持 AutoResearch 根目录，启动命令沿用上文。

## 研究方向（04-A）

项目左侧和顶部“研究方向”可以查看提案、选择代表论文、编辑关键问题/假设/可行性，并确认、拒绝或归档。编辑会保存历史版本并重新回到待确认；旧版本的确认请求返回 409。缺少代表论文时明确标注依据不足。

会话示例：“根据当前论文库整理并保存一个研究方向提案，说明关键问题、待验证空白和单卡可行性；不要替我确认，也不要新增项目笔记。”模型使用 `submit_research_result(kind=direction)`，前端显示提案卡片；只允许用户在方向页正式确认。

读取已有资料复用 `read_file`、`list_directory`、`search_files`，入口 `research://index.json`。方向和论文索引每页 20 条，后续页绑定内容版本；方向详情含当前 Revision。单次资料读取最多 32 KiB，返回完整内容哈希和继续读取提示。逻辑地址始终只读；物理工作区的原路径与写入确认策略继续生效。论文索引和目录当前最多 100 篇。

“继续研究”会新建会话，并填入已确认方向的资料地址与版本，由用户检查后发送。计划审核、任务快照、预算、候选勾选、逐篇分析、证据矩阵和版本化报告已开放。本批验收见 [阶段四记录](phases/04-auto-research/ACCEPTANCE.md)。

## 调研任务、审核与逐篇分析（04-B）

项目顶部/侧栏进入“调研任务”，输入问题并开始；也可以在已确认方向上点击“开始调研”。助手提交计划后，前端展示可编辑说明、检索式与纳入/排除条件，用户确认或取消后从原工具调用继续。普通会话也可以明确要求制定并保存调研计划，Agent 首次提交时绑定本轮任务。

任务页查看冻结范围、计划版本、调用预算、已知 Token 与未知用量次数、执行失败原因。RunID、幂等 OperationID、实际 AttemptID 和内容版本分开管理；确认版本过期返回 409，成功请求重发返回原结果。旧任务输入不随项目修改变化；编辑正式任务问题或完成后重新执行会派生新 Run 并保留旧成果，失败重试保留原 Run 和累计预算。

计划确认后，检索结果按任务去重保存。候选卡片支持查看摘要、勾选、编辑纳入/排除理由、降低分析上限、全部排除后重新检索及取消。确认时自动归档选中论文，原 Agent 收到真实 PaperID，阅读和证据检索限定到纳入集。

当前普通会话使用 single/multi-v9，新自动调研固定使用独立 single-v8 Research Agent。任务页在确认后顺序分析每篇论文；会话只展示状态和结果卡片，展开结果可查看方法、数据集、指标、代码和复现条件及原文引用。结果区分有原文依据、推断、待验证与未知，摘要阅读单独标注。可暂停、继续、取消或单独重试失败篇，成功篇和冻结文档保留；暂停等待当前请求结束后生效。刷新和重启恢复不重复保存已完成结果，预算继续累计。新任务在逐篇结束后自动综合证据矩阵与报告；旧 v6/v7 仍按原结束条件恢复。详见 [阶段四验收](phases/04-auto-research/ACCEPTANCE.md)。


### 独立调研 Agent

在会话发送“开始调研适合单卡复现的时序预测基线”，模型可调用 `start_research(question, constraints, paper_ids)` 启动任务；也可以从项目“调研任务”或已确认的研究方向直接发起。创建后立即返回入口，会话可继续发送其他消息。

点击卡片“打开调研任务”，在独立页面确认计划、审核论文、补充信息，并查看逐篇分析、预算和原文引用。这里支持暂停/继续、失败重试和重新调研；再次调研派生新任务，旧成果保留。刷新或重启后继续读取原任务。内部执行会话不出现在普通会话列表，删除来源会话不会删除研究成果。

任务列表和详情页均提供“删除任务”，点击确认即可，无需输入名称。已完成、失败或取消的任务可以删除；排队、执行、等待输入或等待恢复的任务需先结束。删除会清理任务的计划、候选、分析、报告，以及独立任务的执行记录和检查点；来源会话与论文库中的论文、原文资料和证据保留。普通会话内的旧调研仅删除研究成果，保留聊天与执行记录。内容寻址的产物文件不直接删除，以免影响共享引用。

研究结果由持久成果直接投影到来源会话，不增加模型复述调用；会话下一轮最多自动携带 5 条任务摘要，详情用现有 `read_file(research://runs/<id>.json)` 按需读取。普通聊天和研究各有一个 worker，同类任务排队；它们共用模型连接配置，不共享上下文窗口。任务页使用 SSE 通知刷新，并保留 1 秒轮询补偿。旧 v1–v7 仍沿用原工具定义与恢复方式。阶段四已完成矩阵、Claim、正式报告、共用 UI、报告后续追问、五候选综合场景和故障恢复验收；CLI 命令延期，阶段五远程实验暂缓。

拆分细节及验收见 [独立研究实施](phases/04-auto-research/INDEPENDENT_AGENT_IMPLEMENTATION.md) 和 [阶段四验收](phases/04-auto-research/ACCEPTANCE.md)。


### 证据矩阵与报告（04-C1）

在“调研任务”新建任务并确认计划、纳入论文后，Research Agent 在自己的连续上下文中逐篇阅读，再综合比较、冲突未知、待验证研究空白及下一步实验。任务页下方可展开五字段矩阵，查看报告版本、打开原文引用和导出 Markdown。会话只自动接收摘要、任务入口及报告资料地址。

报告绑定整套矩阵哈希及分析版本，引用核验项目归属、论文/文档身份、原文区间和校验和。报告失败可重试综合，逐篇结果与累计预算保留；用户单独重试失败篇后，旧报告保留并标记为历史矩阵版本，新报告追加版本。程序校验来源和版本，研究结论是否得到语义支持仍需人工复核。

已有读取工具可以按需访问 `research://runs/<id>/matrix.json`、`research://runs/<id>/reports.json`、`research://reports/<reportID>/report.md`。报告不会自动整篇注入会话。细节见 [报告实施](phases/04-auto-research/REPORT_IMPLEMENTATION.md) 和 [验收步骤](phases/04-auto-research/ACCEPTANCE.md)。

### 围绕报告继续对话

任务页选择报告版本后，点击“基于此报告提问”。输入框上方显示报告引用卡片，可以打开、切换版本或移除；后续消息自动沿用，刷新后恢复。来源会话已删除或不存在时会创建普通会话。历史用户消息标出当时引用的版本，编辑和重试仍保留原绑定。

助手使用现有 read_file 按需读取报告、该版本的矩阵及原文证据，不把整份报告预先放入系统提示。新版出现只提示切换；明确要求重新研究时才通过 start_research 委派新任务。切换与移除在下一条消息发送后持久化。离线模式只演示读取与引用，真实问答需配置模型。协议和边界见 [报告对话](phases/04-auto-research/REPORT_CONVERSATION.md)。

### 共用 UI 交互层（Web 已接入，CLI 延期）

`internal/ui` 提供端无关的 `Snapshot`、`Events`、`Respond`、`Act`，使用 `Target{kind: session/research, id}` 绑定目标。快照的 `ui` 字段包含协议版本、结构化交互、可用动作和事件游标；研究快照还携带对应 Run。应用保留项目权限、审核、幂等与恢复规则，UI 不保存另一套任务状态。

普通会话和任务页共用 `UserInteraction`，展示可编辑选项、自定义回答、计划审核和候选审核。新版前端优先消费 UI 协议，旧服务快照保留兼容；研究回答和 SSE 可以直接使用 RunID，不依赖隐藏会话身份。未知交互只读提示，页面刷新或网络断开不会自动批准或取消任务。

未来 CLI 只需添加输入和文本渲染适配器，可直接使用同一 UI 服务或连接现有 HTTP 接口。本轮不增加 CLI 命令。设计与验证见 [UI 实施](phases/04-auto-research/UI_IMPLEMENTATION.md) 和 [阶段四验收](phases/04-auto-research/ACCEPTANCE.md)。
